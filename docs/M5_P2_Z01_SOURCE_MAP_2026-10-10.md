## 1. 고정 객체와 좌표

하나의 source `Profile F`를 고정하고 다음을 모두 같은 객체에서 취한다.

```text
c    := F.data.core
amp  := F.amp
B    := c.pulseStart
L    := c.pulseLength = 13 / c.lam
R    := exp L
a0   := c.exponents 0 = -(1/2 + c.lam)
lj   := c.lower j
uj   := c.upper j
bj(x):= LocalizedMomentRepair.bump (c.lower j) (c.upper j) x
c1(eta) := NSRW.P2.actualSecondRepairCoefficient F eta
K(eta)  := momentScale c 0 * shape eta > 0
```

`c1`는 source `coefficients c.exponents c.lower c.upper
(debt c F.amp eta) 1`이다. `F.reset.coefficients`는 corrected amplitude를 만드는
angular-reset 객체이지 이 axial coefficient가 아니다.

| 좌표 | 정확한 의미 | 첫 repair window |
| --- | --- | --- |
| `r` | pulse-local radial radius, `r >= 1` | `(l0, u0)` |
| `z = log r` | pulse-local log radius | `(log l0, log u0)` |
| `y = B + log r` | global log radius | `(B + log l0, B + log u0)` |
| `X = exp y = exp B * r` | Profile의 global radial radius | `(exp B*l0, exp B*u0)` |

`r ∈ [1,R]`이면 `log r >= 0`, `B > 0`, 따라서 `y >= 0`이다.
source [`Profile.M_at_exp`, 436–442](https://github.com/openai/NavierStokesAndEuler/blob/8937a8f4cbc7abaab5e9e97d1cc7f5d2319d9538/NavierStokes/OutgoingProfile.lean#L436-L442)는
이 조건에서 **직접 equality**를 준다.

```text
localMass F eta r := massMoment c F.amp eta (B + log r)
localMass F eta r = F.M eta (exp B * r)
```

여기에는 별도의 mass scale factor가 없다. 양의 `K`는 아래 pulse 적분의
prefactor다. `M_at_exp`의 equality와 이 prefactor를 섞지 않는다. 별도
`OutgoingDilation`/`XR` 확장은 이 map의 범위가 아니다.

## 2. Support ordering과 endpoint 경계

source의 [`Parameters`, 329–375](https://github.com/openai/NavierStokesAndEuler/blob/8937a8f4cbc7abaab5e9e97d1cc7f5d2319d9538/NavierStokes/OutgoingSchedule.lean#L329-L375)는 다음을 제공한다.

```text
1 < exp(11/lam) < l0 < u0 <= l1 < u1 < R
```

재사용 선언: `one_lt_lower`, `main_end_lt_lower`, `lower_lt_upper`,
`intervals_separated`, `upper_lt_end`. 여기서 endpoint는 `r=R`이며 source의
`c.endpoint`는 **global log coordinate `B+L`**다. 둘을 같은 숫자로 비교하지 않는다.

[`bump_tsupport_subset_open`, 66–68](https://github.com/openai/NavierStokesAndEuler/blob/8937a8f4cbc7abaab5e9e97d1cc7f5d2319d9538/NavierStokes/LocalizedMomentRepair.lean#L66-L68)에
따라 각 bump는 자기 open window 밖과 양 끝점에서 0이다. `correction`은
source `repair`의 두 coefficient-weighted bump 합이다
([repair 정의, 111–115](https://github.com/openai/NavierStokesAndEuler/blob/8937a8f4cbc7abaab5e9e97d1cc7f5d2319d9538/NavierStokes/LocalizedMomentRepair.lean#L111-L115)).

따라서 source 정의들로부터 다음 pointwise reductions가 예상된다.

```text
1 <= x <= l0:
  correction c F.amp eta x = 0
  radialPulse c F.amp eta x = F.amp eta * mainPulse (c.lam * log x)

u0 <= x <= R:
  mainPulse (c.lam * log x) = 0
  b0(x) = 0
  radialPulse c F.amp eta x = c1(eta) * b1(x)
```

이 reductions는 아직 외부 Lean lemma가 아니다. 특히 `x=u0`를 포함해
증명해야 한다. gap의 한 점에서만 부호를 확인하고 open-window 영점을 주장하지 않는다.

## 3. 재사용할 두 mass identity — 아직 Lean 구현 전

`1 <= r <= R`에서 목표로 할 partial-mass identity는 다음이다.

```text
localMass F eta r
  = prefixM c * eta
    + K(eta) * integral(1, r, x^a0 * radialPulse c F.amp eta x)
```

재료는 [`massMoment_at_pulseStart`, 749–761](https://github.com/openai/NavierStokesAndEuler/blob/8937a8f4cbc7abaab5e9e97d1cc7f5d2319d9538/NavierStokes/OutgoingSchedule.lean#L749-L761),
[`mass_integrand_pulse`, 695–713](https://github.com/openai/NavierStokesAndEuler/blob/8937a8f4cbc7abaab5e9e97d1cc7f5d2319d9538/NavierStokes/OutgoingSchedule.lean#L695-L713),
[`exp_weight_substitution`, 635–660](https://github.com/openai/NavierStokesAndEuler/blob/8937a8f4cbc7abaab5e9e97d1cc7f5d2319d9538/NavierStokes/OutgoingSchedule.lean#L635-L660)다.
먼저 global log 적분을 `0..B`와 `B..B+log r`로 나누고, substitution에
`a=a0`, `B=c.pulseStart`, **그 정리의 길이 인자에 `log r`**를 넣는다.
`radialPulse_continuousOn`과 양의 radial interval에서의 power continuity로
필요한 interval integrability를 확보한다.

그다음 [`pulse_closes_prefix`, 619–631](https://github.com/openai/NavierStokesAndEuler/blob/8937a8f4cbc7abaab5e9e97d1cc7f5d2319d9538/NavierStokes/OutgoingSchedule.lean#L619-L631)와
같은 integrand의 `1..r..R` adjacent-interval split을 소비하면:

```text
localMass F eta r
  = -K(eta) * integral(r, R, x^a0 * radialPulse c F.amp eta x)
```

source의 [`massMoment_endpoint`, 846–878](https://github.com/openai/NavierStokesAndEuler/blob/8937a8f4cbc7abaab5e9e97d1cc7f5d2319d9538/NavierStokes/OutgoingSchedule.lean#L846-L878)는
full-length version의 실제 proof pattern을 제공한다. 이번에 읽은 schedule/profile/bounds
선언에서는 위 arbitrary-radius tail identity를 그대로 주는 named theorem은 찾지
못했다. 이 결과는 source 전체에서의 부재 증명이 아니다.

## 4. Z-02에 넘길 두 sign 경로

### Lower boundary

`prefixM c = 4 + integral(0,B, exp t * dropCoefficient c.m t)`이고
`B > 0`, `dropCoefficient_bounds`의 nonnegativity로 `4 <= prefixM c`를 얻는다
([prefix 정의, 381–382](https://github.com/openai/NavierStokesAndEuler/blob/8937a8f4cbc7abaab5e9e97d1cc7f5d2319d9538/NavierStokes/OutgoingSchedule.lean#L381-L382)).
`prefixM_bounds`의 statement는 `0 <= prefixM`일 뿐이므로 strict positivity를
그 statement만으로 얻었다고 하지 않는다.

[`CorrectedPulseAmplitude.amplitude_pos`, 97–105](https://github.com/openai/NavierStokesAndEuler/blob/8937a8f4cbc7abaab5e9e97d1cc7f5d2319d9538/NavierStokes/CorrectedPulseAmplitude.lean#L97-L105)는
실제 `F.amp eta > 0`를 모든 eta에서 준다. `x>=1`에서 `lam*log x>=0`이므로
[`mainPulse_nonneg`, 55–56](https://github.com/openai/NavierStokesAndEuler/blob/8937a8f4cbc7abaab5e9e97d1cc7f5d2319d9538/NavierStokes/PulseAmplitude.lean#L55-L56)를
적용한다. §2의 early correction zero와 partial-mass identity를 연결하면
`eta > 0 -> localMass F eta l0 > 0`를 목표로 할 수 있다.

### Upper boundary — 일반 strict integral positivity를 새로 증명하지 않는 경로

다음을 **whole-line Lebesgue integral**로 정의한다.

```text
I01 := integral(all Real, x^a0 * b1(x))
     = LocalizedMomentRepair.matrix c.exponents c.lower c.upper 0 1
     = rowMoment (c.exponents 0) * exp (beta c 0 * center c 1)
     > 0
```

두 번째 equality는 matrix 정의이고, 세 번째는
[`actual_matrix_entry`, 565–575](https://github.com/openai/NavierStokesAndEuler/blob/8937a8f4cbc7abaab5e9e97d1cc7f5d2319d9538/NavierStokes/OutgoingPulseBounds.lean#L565-L575)다.
[`rowMoment_pos`, 598–599](https://github.com/openai/NavierStokesAndEuler/blob/8937a8f4cbc7abaab5e9e97d1cc7f5d2319d9538/NavierStokes/OutgoingPulseBounds.lean#L598-L599)와
`Real.exp_pos`가 strictness를 준다. 이 경로는 현재 `Parameters`의 기본
lambda 조건만 소비하고 추가 `lam <= 1/120`을 요구하지 않는다.

남은 연결은 §2의 upper-tail reduction과 support localization이다.
`support (x^a0*b1 x) ⊆ (l1,u1) ⊆ (u0,R)`를 사용해 interval integral을
`I01`에 맞추고, coefficient를 적분 밖으로 꺼낸다. 전체 적분의 존재는
`LocalizedMomentRepair.integrable_power_mul_bump`에서 재사용한다.

```text
localMass F eta u0 = -K(eta) * c1(eta) * I01
0 < eta < epsilon(F)  ->  localMass F eta u0 < 0
```

이는 **source-based derivation `SUPPORTED`**다. 현재 compiled surface는 기존
matrix/rowMoment/C04 정리들이며, 위 mass equality와 negative sign은 아직 아니다.

## 5. Domain·continuity와 좁은 다음 행동

현재 대조한 exact mass/cancellation, support, matrix-entry, rowMoment positivity,
amplitude positivity 재료에는 `eta^2 <= 1`이나 `amp > 9/10`이 필요하지 않다.
따라서 이 경로에는 `epsilon <= 1`을 **미리** 추가할 이유가 발견되지 않았다.
이는 아직 미작성인 Z proof의 성공 보장이나 source Specification 전체의 domain
확장이 아니다. 구현 중 실제 lemma가 요구하는 가정은 그대로 남겨 확인한다.

`axial_radial_contDiff c amp eta`는 eta를 고정한 global-log integrand의 continuity를
준다. 이를 적분 primitive의 continuity와 `r>0`에서의 log continuity에 연결해
**같은 `localMass F eta`**의 `(l0,u0)`와 양 끝점을 포함한 continuity를 얻는다.
별도 객체의 continuity를 가져와 IVT를 적용하지 않는다.

```text
제안된 최종 Z target (미구현·미컴파일·미승격):
forall F : Profile, exists epsilon(F) > 0, forall eta,
  0 < eta < epsilon(F) ->
  exists r, c.lower 0 < r and r < c.upper 0
    and F.M eta (exp(c.pulseStart) * r) = 0
```

다음 구현은 **partial-mass identity와 mass-tail identity**로 제한한다.
그다음 lower/upper strict signs, continuity/IVT 순이다. 영점 유일성·first-zero,
uniform/numerical epsilon, Q의 removable extension, upstream theorem 검증은
추가하지 않는다. Z-04 replay/receipt 이전에는 존재 명제를 admission하지 않는다.
